# 截图转招聘内容：本地实施与验收

日期：2026-10-17。状态：本地功能已实施；真实业务截图及公众号后台试用待完成。本次未提交或推送 GitHub。

## 使用入口与实际行为

本地服务：<http://127.0.0.1:8000/imports/screenshots>，导航“截图转内容”，来源监控页也有入口。

1. 同一篇、同一单位公告上传 1–5 张截图，可补来源链接和正文。PNG/JPEG/静态 WebP，单张 10 MiB、批次 25 MiB；长图自动分片，最多 24 片。超限明确报错，不静默截断尾部。
2. 自动识别文字、提取事实和逐岗条件，在同一页对照原图修改。原图、OCR 与手改文本分开保留。轮询不覆盖未保存编辑，重试先保存编辑，队列满也不丢草稿。
3. 人工补齐来源、官方依据、完整材料确认、六项核验和质量分。可保存待核验、提交审核；具备权限的审核员可一次确认并生成微信群文字和公众号稿。
4. 正式复制每次从服务器重新核对权限、状态和版本。旧稿在材料变化、到期、撤销或复核失效后不能继续复制。不自动发送群消息或发布文章。

B/C 可先保留待人工核验，不能借截图绕过学生受众要求；D 不能直接改选岗位强升，可保留原记录并派生其他岗位。多岗位的独立条件、公共限制、收费招聘和培训贷检查均在确认前执行。

覆盖存储边界、私有图片授权、格式/像素/配额、持久队列与租约恢复、跨批缓存、失败阶段重试、证据与角色边界、事务回滚、并发版本、审核权限、旧稿失效、旧页面 AI 提炼人工稿保护和微信验证页回退。HTTP 闭环使用隔离数据库和假模型，测试不向正式岗位库写入合成材料。

浏览器在独立 8003 验收服务上实际完成：选图上传、自动识别、同页修改、人工 87 分确认、生成、复制。群消息剪贴板包含岗位、独立申请条件、邮箱、日期及官方链接；公众号剪贴板同时含 `text/html`（4062 字符）与 `text/plain`（442 字符）。未把复制记作发送。390×844 视口没有横向溢出；相关页面控制台无 error/warn。

普通本地 contenteditable 粘贴检查保留了正文内容，但当前内置浏览器自动化粘贴路径没有保留 HTML 样式，另一 HTML 格式粘贴尝试显示为字面源码。因此仅确认富文本载荷已生成、纯文本内容可粘贴，**未验收真实富文本编辑器样式兼容性，更未实测微信公众号后台**。用户实际粘贴后仍需检查。

## 真实接口测试：只使用合成招聘材料

使用现有配置的百炼 OCR 和当前文本提供方；密钥未打印、未写入源码。所有图片、OCR、模型响应和失败记录仅存于 Git 忽略的 `outputs`。没有真实学生资料或私聊截图参与测试。

初测发现 generic OCR 提示词会得到纯坐标，不能按 HTTP 成功判定识别成功。按[百炼官方 OCR 文档](https://help.aliyun.com/zh/model-studio/qwen-vl-ocr)改用通用文字识别指定 Prompt，纯坐标结果拒绝为 `ocr_no_text`。精确纯色分片本地跳过；非纯色仍识别，整批无文字不能继续。缓存规则已升版本，避免复用旧坐标输出。

| 合成案例 | 修正后观察 | 边界 |
| --- | --- | --- |
| 清晰单岗位 | OCR、字段及核心内容检查通过，27.52 秒 | 不代表真实截图准确率 |
| 4500 像素长图，截止和邮箱在底部 | 中间空片不阻断，尾部保留，11.47 秒 | 空片仅在精确纯色时跳过 |
| 两张重叠连续截图 | 原文与核心字段检查通过，15.98 秒 | 未宣称三张真实截图已测 |
| 独立配色海报版式 | 核心内容检查通过，11.94 秒 | 与清晰截图不同图片，不重复计数 |
| 学生岗与高级岗混合 | OCR 完整；文本模型先后生成拼接标题、跨岗引用或无证据分类，服务拒绝 | 安全停在人工校对，不算端到端自动提取成功 |
| 明示模糊邮箱 | OCR 曾去掉问号但保留“不清晰”提示；文本结构失败，后续一次请求超时 | 保留原图/正文，需人工核验；不能保证 OCR 不猜字符 |

共 6 组中，4 组达到合成质量断言，2 组需人工恢复。已针对模型输出契约强化逐岗证据边界和严格照录要求，但未放宽原文引用校验来追求成功率。联系方式自身引用有“不清晰/模糊/不确定”等标记或值含问号时强制待核验；若 OCR 和引用都遗漏异常，仍只能靠人工对照原图发现。没有虚构 OCR 准确率，也没有用假响应代替真实接口测试。
