# 立信学生招聘来源扩充执行方案

> 执行时使用 executing-plans 分任务推进，每个模块测试、汇报后再进入下一阶段。本文件是实施前方案，不代表入口已接入或正式启用。

**日期：**2026-09-16

**Goal：**扩大上海立信会计金融学院学生可投岗位的供给，重点补充民企、中小企业、专业服务及非金融行业职能岗位。

**Architecture：**保留现有来源目录、适配器、B 类试采、准入审核、正式采集及人工发布审核架构。公开渠道为主；招聘 App 人工精选仅作备选，不开发登录绕过或批量 App 爬虫。

**Tech Stack：**现有 Python / FastAPI / SQLAlchemy / httpx / pytest；首批不增加浏览器采集集群、付费 API 或新数据库。

## 1. 范围与放宽边界

- 地点仍以明确上海岗位为主；不在本轮悄悄取消现有上海校验。全国招聘中只提取明确上海的子岗位。
- 不限制企业上市状态、规模、知名度、所有制；不因企业不知名直接排除。
- 除金融机构外，覆盖商贸、物流、制造、互联网、专业服务等行业的匹配岗位。
- 覆盖实习、校招、明确接受应届生的社会招聘；经验不限但受众不明确的岗位进入待补证据，不直接合格。
- 薪资未披露不直接淘汰，不生成推测薪资；销售、派遣、外包、实习均明确标注。
- 不放宽真实雇主、岗位正文、投递证据、过期排除及人工审核；收费培训转就业、押金、明显虚假招聘不得发布。
- 招聘会邀请函不是岗位。可人工从参会企业清单发现雇主，只有取得具体职位正文和投递证据后才进入岗位审核。
- 学校转发不等于校方担保；平台发布者也不一定是实际雇主。不使用“二本友好”“保证录取”推断标签。
- 校内登录或仅限本校申请的来源不得绕过；不能把其他高校校内专属岗位推荐给立信学生。

## 2. 专业覆盖基线

依据学校公开的《2025年本科专业设置情况》，而非只覆盖会计和金融。它不是已核对的2026全量目录，执行前复查有无更新；停招专业可能仍有在校生，不直接删除。

| 方向 | 专业举例 | 岗位发现关键词举例 |
| --- | --- | --- |
| 财会审税评估 | 会计、审计、财务管理、财政、税收、资产评估 | 核算、审计助理、税务助理、评估助理、资金结算 |
| 经济金融保险 | 经济、金融、投资、保险、精算、金融工程等 | 业务运营、风险支持、核保理赔、金融机构实习 |
| 商贸物流语言 | 国际经贸、国际商务、物流、英语、商务英语等 | 外贸、供应链、采购助理、跨境电商、国际业务 |
| 管理与营销 | 工商管理、市场营销、人力资源、电子商务等 | 人事助理、运营、客户服务、营销、管理培训生 |
| 数学数据与技术 | 统计、数学、计算机、数据科学、智能科学等 | 数据分析、软件测试、系统支持、开发实习 |
| 法律公共与人文 | 法学、行政管理、社会工作、汉语言文学等 | 法务助理、合规助理、行政、社会服务、编辑内容 |

关键词用于发现和分类，不等于满足任职要求；保留招聘原文的专业、证书、技能、届别条件。“专业不限”单独标注，不自动关联所有专业。

官方依据：https://www.lixin.edu.cn/gk/xxgklm/jhgl/hkzysz/hkzysz/150261.htm

## 3. 候选入口与分批扩充路线

从“首批2个来源”升级为**五个批次、最多16个候选入口**的路线图。这里的“批次”是验证和上线顺序，不是要求一次性写16个采集器：同批入口可以完成勘查，但只有达到准入条件的来源才进入下一步正式采集。

新来源和已有目录项分开统计；已在目录里的B类来源不能因列入新批次被重复创建。每一批结束后只基于真实试采结果决定下一批，不承诺所有候选最终可用。

| 批次 | 候选入口 | 主要补足方向 | 本批完成条件 | 停止条件 |
| --- | --- | --- | --- | --- |
| 0：基线 | 现有A类来源、已登记B类来源状态 | 明确当前供给缺口和可复用来源 | 输出按专业方向的来源/岗位基线，不改来源状态 | 未取得基线时，不开始大量新增 |
| 1：高优先级聚合 | 上海商学院、上海市企业服务云 | 商科实习、民企、中小企业职能岗 | 至少1个完成端到端接入；另1个完成勘查结论 | 两个入口均无可追溯详情或投递证据时切换批次2替补 |
| 2：上海应用型高校 | 上海应用技术大学、上海对外经贸大学、上海理工大学 | 商贸、物流、运营、数据、财会及外语方向 | 每站完成10条以内近期样本勘查，选最多2个开发 | 本校专属、登录限制或无上海匹配岗位则仅保留人工发现 |
| 3：综合高校与国家平台 | 上海大学、华东理工大学、华东师范大学、国家大学生就业服务平台上海岗位 | 补数据技术、管理、人文及全国企业的上海岗位 | 从中选择最多2个结构稳定、非校内专属入口进入适配 | 403、验证码、详情正文缺失或大量非上海岗位导致筛选成本过高即退出 |
| 4：地方公共与产业园区 | 上海公共就业平台、松江区、浦东新区、临港新片区、漕河泾开发区 | 区属企业、园区企业、产业服务、基层和公共岗位 | 每个入口先确认有持续职位列表；最多2个进入适配 | 只有公告/公示、无持续职位级详情时不采整站新闻 |
| 5：人工补给池 | 招聘App人工精选、企业官网、HR投稿 | 解决自动来源覆盖缺口，发现细分岗位 | 每周固定限额导入并完成原文核验 | 不做登录绕过、自动化批量抓取或无原链接搬运 |

**并发控制：**在任何时点，最多同时开发2个新适配器、同时进行4个来源的试采。其他入口可完成只读勘查，但不进入代码开发队列。这样可以保证人工审核、报错诊断和测试都跟得上。

## 4. 与现有代码衔接

已检查：

- `app/sources/catalog.py`：目录定义，新 B 来源默认禁用；目录同步不得覆盖运营人员启停状态。
- `app/services/source_trials.py`：`TrialBudget`、`TrialCollection`、`TrialAdapter`、`TRIAL_ADAPTERS` 和来源键校验；目前不是登记任意网址就能试采。
- `app/services/real_collection.py`：`collect_due_sources` 按适配器分派；只添加试采适配器不会产生正式岗位。
- `app/services/source_candidate_policy.py`：试采与正式采集共用的 `SourceCandidate`、`evaluate_candidate`；目前受众不明确进入 `needs_evidence`。
- `app/services/source_admission.py`：连续试采及人工准入。
- `app/services/source_request_budget.py`、`app/services/outbound_policy.py`：请求预算和出站地址安全检查。

不整体重构这些文件。每新增一种经证据验证的页面结构，建立单独适配器模块及 fixture 测试；同构站点确认字段一致后才能复用，不凭首页相似判断接口相同。

## 5. 分阶段执行任务

### P0：基线与批次1入口勘查（约1—2个工作日）

产物：新建 `docs/sources/LIXIN_SOURCE_PROBE_REPORT.md`，每个入口一条记录；此阶段不写入正式岗位库。

- [ ] 从官方导航确认来源归属、列表地址、详情地址，记录检测时间与访问限制。
- [ ] 每站检查最近30天最多10条公告详情；不足时扩大至90天并标记老样本，不能计入近期新增。
- [ ] 记录：真实雇主、职位、上海地点、日期、专业/经验/届别、正文、投递证据、是否本校专属。
- [ ] 记录公开 HTML 或匿名接口的实际请求方式、分页参数和响应字段；不猜测 API 地址。
- [ ] 分类：可自动适配 / 附件人工辅助 / 登录限制人工入口 / 无近期匹配样本。
- [ ] 每站最多投入半个工作日；卡在验证码、校内网络、403限制时更换下一候选，不绕过。
- [ ] 批次1选最多2个能取得真实合格样本、维护成本可控的来源；商学院与企业服务云是优先候选而非强制结果。
- [ ] 对批次2—4仅完成来源级勘查排队表，记录“未开始 / 勘查中 / 可开发 / 人工补充 / 不适合”五种状态；未轮到的来源不做试采。

验收：每个批次1入选站至少有可追溯的列表、详情及投递证据；不够2个则如实交付勘查结果并从批次2替补，禁止虚报已接入。

### P1：逐源完成解析与双通路接入（每种页面结构约1—2个工作日）

计划新建文件（仅对P0通过的候选实施）：

- 商学院：`app/sources/sbs_jobs.py`、`tests/test_sbs_source.py`、`tests/fixtures/sbs/`。
- 企业服务云：`app/sources/ssme_jobs.py`、`tests/test_ssme_source.py`、`tests/fixtures/ssme/`。
- 若替换候选，先在勘查报告中列明对应文件名与稳定 source_key，再实现。

修改范围：`app/sources/catalog.py`、`app/services/source_trials.py`、`app/services/real_collection.py`，必要的既有测试；不修改数据库结构作为默认方案。

接口：适配器产出既有 `SourceCandidate`；试采包装为 `TrialCollection`，满足 `TrialAdapter`；正式采集复用同一解析和 `evaluate_candidate`，接入现有入库函数。不得让正式采集绕过试采筛选。

- [ ] 先保存经脱敏的真实 HTML/JSON fixture，编写失败测试：正确解析、正文为空、相对链接、分页、缺失日期、附件依赖。
- [ ] 运行该来源测试，确认是目标功能缺失导致失败，再实现最小解析逻辑。
- [ ] 增加稳定身份测试：同一公告多个职位分别识别；重复抓取不新增；正文更新不伪装新职位。
- [ ] 目录使用固定键，例如 `sbs-jobs`、`ssme-jobs`；B类默认禁用。同步重复执行不产生重复行、不重置人工状态。
- [ ] 同时注册 `TRIAL_ADAPTERS`、来源键校验及正式采集分派。
- [ ] 覆盖超时、403、429、外站跳转和私网URL拒绝；重定向每跳重新检查目的地。
- [ ] 测试未准入不参与日常采集；准入后同一 fixture 能经正式流程生成待人工审核岗位。
- [ ] 每完成一个来源独立验收，不等所有来源一起测试。

此阶段的实际选择器、接口参数与字段映射必须以P0样本为依据，在实施前补入勘查报告；本方案不编造外部接口或提供无法验证的解析代码。

### P2：受众规则复核（不与首个适配器同时扩大行为）

先保持当前候选规则，复盘P1样本中 `TARGET_AUDIENCE_UNCLEAR` 的原因。专业范围按第2节扩充审核口径，不把关键词命中当作合格资格。

- [ ] 对明确“应届生可投”但表达未识别的真实样本，先补 `tests/test_source_candidate_policy.py`，再扩展学生表述识别。
- [ ] 反例必须包含“经验不限但要求已毕业三年”“高级岗公告同时提到校招”“会计专业限定但只命中金融关键词”。规则应基于岗位段落，不能被同页其他职位污染。
- [ ] 经验不限、0—1年且未明确学生可投：仍待补证据，不自动合格。
- [ ] 试采规则发生语义变化时提升 `RULE_VERSION`，旧版本试采不得直接准入，重新累计。
- [ ] 不更改上海边界；不以专业目录新增为由重置现有来源状态。

如现有字段无法表达新标签，本阶段先在审核说明保留原文，不临时扩数据库；独立提出字段迁移方案后再实施。

### P3：真实试采及人工启用（至少跨2个自然日）

保持既有准入条件：最近连续3轮、相邻至少8小时、跨至少2天、每轮详情成功率至少90%、每轮至少1条合格岗位，累计至少10个不同公告及3条不同合格岗位，适配器及规则版本一致，最后由管理员确认。

注意：默认每轮只读3条详情，3轮最多9个公告，无法满足累计10个公告。正式准入试验应使用每轮最多10条详情，并确保分页/样本选择能覆盖不同公告；不能通过反复抓同样几条凑数。

在 `网页` 目录执行，先完成适配器注册和目录同步、确认正确数据库：

```powershell
& .\.venv\Scripts\python.exe -m app.cli source-trial --source-key sbs-jobs --pages 2 --list-limit 20 --detail-limit 10 --total-seconds 180
```

替换为已经注册的真实来源键。每轮请求间隔至少1秒、单请求最多12秒，总预算180秒；按更严格的网站要求降低频率。跨日轮次通过已有调度机制或人工执行，不通过持续阻塞等待或伪造时间完成。

- [ ] 逐轮记录 run_id、版本、不同公告数、岗位数、失败原因。
- [ ] 达标后人工核对样本，再从既有界面启用。
- [ ] 不达标保留B类/人工补充，不能为凑来源数降低门槛；低频优质来源先人工监控。
- [ ] 启用后验证实际日常任务能采到该来源，而非只验证试采按钮。

### P4：批次门槛与7—14天效果复盘
