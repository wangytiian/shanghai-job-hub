# 截图转内容：问题优先与一次终审

用户于 2026-10-18 确认对话中方案，授权实施。现有截图功能及预填恢复已经完成，不重复开发。继续在含未提交功能的 `feat/sspu-a-source` 工作目录内迭代；不创建缺失这些功能的 HEAD 工作树，不提交或推送 GitHub。

## 目标

上传后由 AI 整理；页面先显示摘要与两渠道内部预览，运营者只处理真正影响成稿的问题，最终一次明确点击完成人工核验。保存草稿始终宽松。缺失事实不编造，真实限制不通过隐藏字段绕过。

## 字段与阶段

- 正式稿必需：单位、具体岗位或所选岗位、地点、学生受众、可追溯来源和有效官方投递依据。
- 日期：完整可解析日期，或明确保留“公告未明确统一截止时间”；未知年份不能猜。过期不能通过。
- 条件必需：邮件投递须真实邮箱；必要附件、多岗独立条件与公共限制须处理；跨单位/岗位边界或受众疑点须解决。
- 可选：薪资、职责、专业标签、岗位族、非关键补充说明。缺失不拦；不确定内容不能出现在正式稿。关键资格/收费/岗位归属不可作为选填隐藏。
- `evidence/confidence/rationale/uncertainties` 是 AI 诊断，不作人工必填或成稿门槛；事实的 `evidence_refs` 仍严格保留。
- AI 分类、来源、岗位等明确值优先填入；无具体岗位的宣传图仅内部公告草稿，不制造岗位名称。

## 界面

三步为“上传材料、处理问题、确认与复制”。摘要和内部预览优先，默认收起完整表单和诊断。问题区分红色阻断、黄色提醒、信息说明；顶部及操作区同步数量。每个问题含稳定字段路径、代码、中文原因、解决方法、定位锚点。首次加载和提交时均能一次显示全部已知问题；红色之外必须有文字和辅助技术语义。

保留完整编辑能力、原图和连续原文定位。新增/重命名“AI补全与整理”，复用 OCR，最多一次自动修复；不得反复整包覆盖已验证事实。只有有依据的同义表达和标签格式规范化才能消除伪冲突，日期/金额/邮箱/学历/否定/范围的真实差异保留。

## 一次终审与评分

用户看见本版单位、岗位、受众、地点、投递和时效摘要，明确点击“我已核对关键内容，确认生成”。后台记录真实操作者、时间、当前 import/content/job 版本和确认范围，兼容六项核验，不伪造多次人工操作。无审核权限者只能提交审核。

新版截图审核以明确成稿条件为门槛，取消手填质量分；不把旧分数自动抬至 70/85/100。质量分仅参考。只对获得当前版本、服务端生成的一次终审证明的截图岗位应用此策略；旧流程和其他抓取岗位的 70 分规则保持原样。审核、生成、复制必须一致复验该证明及其他全部规则。AI 不能创建证明。

证明放入现有 confirmed_content_json 的可选版本化顶层属性，验证来源 import、job/内容版本与事实摘要哈希；旧快照兼容。任何事实修改、重提取、过期、撤销和并发冲突仍使旧证明与复制稿失效。无需数据库迁移或新依赖。

## 失败与草稿

新版交互先单独安全保存草稿及使旧审批失效，再校验和进行原子审核/生成。后续失败不能抹掉用户输入；正式岗位状态、审核记录、确认快照、分发项仍原子提交或回滚。旧 API 的原有事务语义保留。C 级或受众不明要明确“草稿已保存，尚不能成稿”，不能展示完成。

## 安全与验收

不改变凭据、模型提供方、公开抓取策略、公众号/群自动发送能力。测试仅隔离数据库，真实用户材料仅只读验收；不自动审核用户岗位。重点覆盖多错误同时定位、选填缺失、诊断冲突、费用/资历/日期/入口风险、一键权限与版本、低分旧流程、证书伪造/过期、保存后审批失败、现有回归和窄屏操作。最终更新 README 与项目台账，保留备份及测试证据。
