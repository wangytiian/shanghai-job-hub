# 国家大学生就业服务平台上海岗位接入设计

日期：2026-09-06  
状态：等待用户审阅后实施

## 目标

将国家大学生就业服务平台中可公开访问、工作地点为上海的职位，作为独立 A 类来源采集到现有工作台。所有新记录继续进入“待核验”池，不能自动审核、发布、发送公众号或替用户投递。

## 已验证事实

- 列表接口：`https://www.ncss.cn/student/jobs/jobslist/ajax/`；`areaCode=310000` 返回公开 JSON。
- 列表支持分页，每页 10 条；返回岗位 ID、岗位名、企业名、薪资、学历、来源单位、发布时间与更新时间等字段。
- 详情入口：`https://www.ncss.cn/student/jobs/{jobId}/detail.html`；公开 HTML 可读取。
- 详情中“投递简历”代表仍可投递；出现“职位已下线”即不入库或标记为过期。

## 方案比较

1. **推荐：独立 NCSS 适配器。** 读取上海筛选 JSON、再逐条读取详情，复用现有的待核验、内容版本和过期机制。数据可追溯，且不依赖浏览器自动化。
2. 仅将平台作为人工链接库。实现最小，但无法解决每天人工查找与筛选成本。
3. 抓取搜索引擎结果。覆盖不稳定、时效性和去重不可控，且不能证明仍在投递；不采用。

## 采集边界

- 每次最多读取前 3 页（最多 30 条）；详情请求间隔至少 0.5 秒，单请求 12 秒。
- 只使用平台公开的列表与详情 URL；不登录、不模拟投递、不触碰收藏、举报或个人资料接口。
- 详情必须同时满足：正文可提取、未显示“职位已下线”、页面存在“投递简历”。否则统计为跳过，不创建正式岗位。
- `areaCode=310000` 仅表示列表筛选，仍从详情正文保存地点证据；列表与详情矛盾时保持“待人工核验”。
- 保存平台返回的“来源单位”和企业名；它们不是企业官网证明。岗位的 `source_url` 指向平台详情，`official_url` 仅在详情明确给出企业官网时填写。
- 对同一来源使用“平台 jobId + 企业名”作为稳定身份；正文变化触发现有版本更新逻辑。旧详情下线时复核并走现有过期阻断。

## 组件与数据流

```text
NCSS 上海列表 JSON
  -> ncss.py：过滤、解析列表
  -> NCSS 详情 HTML
  -> ncss.py：正文、可投递状态、企业/地点/日期证据
  -> real_collection.py：复用 _save_detail
  -> Job（待核验） -> 既有人工结构化/审核/发布流程
```

新增 `app/sources/ncss.py`，仅负责公开 HTTP 请求和解析；新增 `collect_ncss_shanghai_jobs()`，仅负责将通过入口条件的详情交给 `_save_detail`。目录增加“国家大学生就业服务平台上海岗位”A 类来源和 `ncss_shanghai_jobs` 适配键。每日采集分发只增加一个分支，不引入新服务、队列、模型、账号或浏览器集群。

## 失败与异常处理

- 列表 JSON 结构异常、非 200、空列表：本轮来源失败，但不将其解释为没有岗位。
- 单条详情失败、正文不足、下线或不可投递：单条跳过/失败，继续其余职位；不得写入可发布岗位。
- 三次连续来源级失败后沿用现有自动暂停规则。
- 任何真实采集均保留请求边界和来源状态；隔离试采使用临时 SQLite，不向正式库写岗位。

## 验收和测试

1. 离线 JSON 测试：仅保留上海列表记录、正确翻页、重复 ID 去重。
2. 离线 HTML 测试：解析可投递详情；“职位已下线”、正文过短、缺少投递入口均拒绝。
3. 采集测试：首次创建、二次无重复、正文变化更新、下线阻断、地点不凭名称推断。
4. 使用真实公开接口在隔离 SQLite 试采两次，报告新增、无变化、更新、下线/跳过和失败数。
5. 仅在测试、真实试采与目录初始化稳定后启用 A 类来源；最后运行完整本地与 Docker 测试。

## 不在本次范围

- 自动投递、账号登录、收藏、岗位举报或任何代表用户的站外操作。
- 企业官网真实性自动确认、薪资/地点的 AI 自动修正。
- 采集全国其他城市、搜索引擎结果或 Hotjob 等动态第三方校招系统。
