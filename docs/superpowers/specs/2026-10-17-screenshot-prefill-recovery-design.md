用户已在“AI 自动填好、只核对疑点；固定格式、保留有效字段、失败重试”的建议后回复“可以 做修改+优化”，据此实施，不重复要求确认同一范围。

## 设计

保留“两阶段 OCR→文本字段提取”及现有持久队列；在字段阶段增加专用固定 JSON Schema 请求、一次输出修复机会和逐字段验证恢复。与只换更大模型相比，这直接解决输出契约；与无条件放宽校验相比，不降低证据和人工审核边界。

- 新纯函数模块提供截图 JSON Schema（固定全局字段、各岗独立字段、公共条件、警告），以及逐字段恢复和修复提示词。旧严格解析接口行为保持，供安全回归继续使用。
- AI 服务新增截图专用冻结请求，Chat Completions / Responses / 百炼采用各自结构化输出参数。明确不支持 schema 的400/422可至多降级一次普通JSON调用；401/403/429/5xx/网络超时不冒充格式不兼容。所有异常只暴露受控摘要，不记录密钥/HTTP原始响应。
- 当前已知 gpt-5.6-terra 的截图请求使用低延迟推理设置；不影响旧功能，不假设所有中转均支持扩展参数。不改变用户模型、Key、服务商或图片出站目的地。
- 文本输出首轮严格校验失败时，收集已验证的字段，自动请求修复一次；修复仍失败时保留有效字段，并逐项显示“待核对/原因”。绝不把无依据值保存为可审核事实。
- 恢复仅接受合法 JSON 对象，可剥离单一外围 markdown json fence；不使用eval，不扫描任意文字中的猜测JSON。每个事实仍通过原文连续引用/枚举/日期年份/联系方式不确定性/角色边界验证。
- 跨岗位引用只隔离坏字段，不能将另一岗位资格当作正确字段；岗位标题无效时不保留该岗条件。公共条件校验失败必须保留可读警告并阻断直接审核，不能静默删除。
- 分段结果缓存包含当前规则版本；材料/配置变化、租约失效、人工编辑等继续使用现有双版本防护，旧结果不得覆盖人工修改。新结果落地仍是未审核草稿。
- 页面明确显示当前OCR/文本模型、已填字段数量、待核对项目和一键“AI重新提取字段”；不把AI成功等同审核通过。来源原链接只有用户给出或原文可见时才能填，不编造未知日期/链接。
