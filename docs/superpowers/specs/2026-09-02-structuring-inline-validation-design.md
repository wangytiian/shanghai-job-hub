# 公告结构化表单内校验设计

## 目标

结构化表单提交失败时保留在当前页面，显示可理解的中文反馈；不把 FastAPI 的 JSON 错误页暴露给运营人员。

## 交互规则

- 浏览器原生必填和 URL 格式错误由字段本身阻止提交，并显示字段提示。
- 服务端业务校验失败时，页面顶部显示“还需补充或处理 X 项”，每项对应到具体字段并标红。
- 附件待核验、多岗位未核验、公告信息不足属于黄色状态提醒：记录可保留为待核验，但不可进入待审核。
- 校验通过时才跳转岗位详情，并进入待审核。
- 表单回显本次填写内容，避免运营人员重新录入。

## 边界

- 不改变既有事实校验标准，也不允许 AI 或人工虚构字段。
- API 仍使用 HTTP 400 表达程序调用错误；仅浏览器表单提交改为返回结构化页面。
