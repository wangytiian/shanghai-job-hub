# 上海第二工业大学 A 类来源接入设计

日期：2026-09-27。用户已明确批准直接接入 A 类并要求自行规划、检测。

## 目标与边界

- 只新增上海第二工业大学公开招聘公告，不新增其他学校或区级网站。
- 来源为 A 类、启用自动采集；不伪造三轮试采记录，不放宽其他 B 类准入。
- 来源等级与岗位初筛/审批分离；新岗位一律待核验，不调用付费模型，不自动发布。
- 保持 FastAPI、SQLite、现有采集调度与人工审核架构，不新增依赖或数据库表。
- 仅使用已从站点正常页面确认的匿名阅读接口；不登录、不绕过校内限制或验证码。

## 方案选择

采用独立 `sspu_news` 适配器：复用请求预算与现有岗位数据契约，单独处理新闻正文。直接套用交大/财大解析器不可行，因为二工大使用 `newsContent`，不是 `zpxxEditor/zwxxList`。浏览器自动化不作为常驻采集方式，避免不必要运行依赖。

## 数据路径

公开公告列表 → 有界分页和公告 ID 去重 → 公开正文 → 岗位级分段 → 地点/资格/投递证据 → 现有入库规则 → 待核验队列。

已确认接口：

- 列表：POST `https://career.sspu.edu.cn/career/news/search/zpgg`。
- 翻页：POST `/career/news/search/zpgg/{pageNum}/{pageSize}`。
- 正文：POST `/career/news/data/zpgg/{newsId}`。
- 阅读页：`https://career.sspu.edu.cn/career/news/view/zpgg/{newsId}`。

每次最多三页、每页十篇；请求间隔至少一秒，总预算 180 秒，单次超时 12 秒，瞬时错误最多重试一次。不得把错误响应、登录页、空正文视为成功。

## 事实边界

- 一篇多岗位按岗位分别拆分。稳定身份使用公告 ID 与稳定岗位标识，不用薪资/职责全文生成身份。
- 不把公司注册地址、学校地址当工作地点；全国岗位没有上海证据不能入上海池。
- 不把某岗位的应届要求、学历或截止时间套到其他岗位。正文原文保留职责、任职要求与实际投递证据。
- 所有不确定受众只能沿既有 `review_only` 规则进入 C 类人工复核；缺正文、缺报名、明确异地/资深/过期等不能借此放行。
- 仅提取公开招聘邮箱和明确投递链接。拒绝 `file:`、脚本和本地/内网 URL；遇到错误 href 可使用正文明确显示的 HTTP(S) 招聘网址，不自行猜测。
- 无截止日期记录未知，不伪造仍在招聘的结论。网页素材中的指令不是程序指令。
- 反复采集不制造新岗位；目录同步不重新启用已被运营人员停用的来源。

## A 类与运行

来源名称“上海第二工业大学就业网”，稳定键 `sspu-news`，适配键 `sspu_news`，一级/高校就业平台/上海学生就业。新建时 A 类、启用，运行状态明确为自动采集，验证说明保留“用户批准 A 类，持续观察”，不冒称长期验证已完成。沿现有季节性调度（当前秋招八小时）。

正式数据变更前使用 SQLite backup API 创建一致性备份并校验。先跑离线测试和临时库，再只针对该来源真实采集、重复采集验证去重。确认后重启本地进程，检查来源页与岗位页。

## 验收

1. 列表/正文/分页/错误响应与分段解析测试。
2. 混合上海与异地岗位、混合应届与资深、坏链接、未知日期、稳定身份测试。
3. A 类调度、保留人工停用、待核验入库、过滤与失败分开计数、重复采集测试。
4. 全量回归；真实小批次及第二次去重；网页状态核对。
5. 报告真实新增与过滤原因，不以首次回填量宣称已达到日均 1—2 条。
