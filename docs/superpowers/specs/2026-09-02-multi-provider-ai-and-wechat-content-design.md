# 多模型 AI 与公众号内容提炼设计

## 目标

在不改变人工审核和事实核验边界的前提下，新增 GPT/OpenAI 兼容中转 API，并让公告结构化、入库筛选和公众号正文可选择当前启用的文本模型。

## 模型提供方

系统保留阿里云百炼 Qwen，并新增 `openai_compatible` 提供方。GPT 中转配置包括 API Base URL、API Key 和文本模型名；Base URL 与模型名保存在本地数据库，API Key 仅保存在 Windows 凭据管理器。每个提供方独立保存、独立测试并显示脱敏状态。

设置页增加“当前文本模型提供方”选择。Qwen 保持默认；只有经过保存、开启并且密钥存在的提供方可以被选为当前模型。OCR 仍使用 Qwen，GPT 中转不承担 OCR。

## 调用边界

业务模块不再直接调用 Qwen 客户端，而使用 `complete_text(session, prompt)`。该接口根据当前提供方返回文本；未配置、未开启或连接失败时返回可理解的错误。现有公告初筛和公告结构化都通过此接口调用。

## 公众号内容提炼与版式

针对已经通过人工审核、且可发布的岗位，AI 仅基于岗位已核验字段和采集原文输出受约束 JSON：一句招聘导语、岗位内容、申请条件、求职建议和投递提示。每个事实类句子必须能在原文或已核验字段中找到依据；未写明的信息留空，不能补造薪资、编制、转正、专业不限、截止时间或企业介绍。

渲染器使用该 JSON 及已核验字段，生成与 FINJOB 参考结构一致的公众号 HTML：大标题、信息栏、简短导语、`OVERVIEW / 招聘速览`、`ROLE / 岗位内容`、`ELIGIBILITY / 申请条件`、`CAREER GUIDE / 求职建议`、`APPLY / 如何投递`、来源与非官方声明。AI 不直接输出 HTML，确保复制到公众号时样式稳定。

模型未配置、调用失败或 JSON 校验失败时，保留现有固定模板作为降级稿，并在后台明确提示“已使用基础稿”；不得自动发布。

## 验收

- 两套 API 配置互不覆盖，密钥不进入数据库、页面或错误信息。
- GPT 中转测试请求使用 OpenAI 兼容 `/chat/completions` 协议。
- 选择 GPT 后，结构化和初筛通过 GPT 调用；未选择时继续 Qwen。
- AI 文案只使用可验证事实；不合规字段被丢弃并使用安全默认文案。
- 无 AI 或 AI 失败时仍可生成可复制的基础公众号草稿。
