# 非招聘通知拦截与队列摘要设计

## 目标

阻止体检、面试、录用、公示等招聘进度通知进入公众号或微信群发布流程；同时让内容队列只展示简短摘要，不再显示包含网站导航和页脚的完整采集原文。

## 分类规则

系统新增公告类型字段，默认值为“待判断”。运营人员可确认：

- 新招聘：实习、校招或毕业两年内初级岗位，可继续结构化和审核；
- 招聘进度通知：笔试、面试、体检、资格复审、录用、公示、成绩等，只保留记录，不可进入发布；
- 非招聘信息：淘汰。

标题或原文命中“体检、面试、录用、公示、拟录用、成绩、资格复审”时，系统自动建议“招聘进度通知”。该建议不是最终审核决定，但在未人工改为“新招聘”前，结构化提交和发布均被禁止。

## 页面行为

待核验详情页显示公告类型建议与三个操作：确认为新招聘、标记为招聘进度通知、淘汰。只有确认为新招聘后才显示“开始公告结构化”。

已错误进入待审核或可发布的进度通知，标记后会变为“仅归档”，并删除该岗位现有的公众号和微信群待发送队列，避免继续误发。

## 队列摘要

公众号和微信群队列预览只显示招聘单位、岗位、类型、适合人群、地点、截止日期、官方入口和短核验说明。完整采集原文仅在岗位详情页显示，不会进入队列内容、公众号草稿或群消息。

## 边界

- 不使用 AI 推断事实；本期使用确定性关键词建议和人工确认；
- 后续 AI 可辅助判断类型和预填字段，但不能自动改为新招聘或自动发布；
- 已发布内容不自动撤回，需运营人员按更正流程处理。

## 验收

1. 命中“体检通知”的公告默认建议为招聘进度通知，不能结构化；
2. 人工确认为新招聘后，才可进入结构化；
3. 标记进度通知后，既有待发送队列被移除；
4. 队列预览不包含完整原文、网站导航或页脚；
5. 全量自动化测试通过。
