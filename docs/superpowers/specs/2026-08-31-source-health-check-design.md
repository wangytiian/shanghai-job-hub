# 来源官网连接自检设计

## 目标

让运营人员在来源监控页主动检查未自动采集官网的可访问性，并看到可解释的结果，从而区分“尚未适配”“官网连接失败”和“已可访问但仍待开发适配器”。

## 方案选择

采用单来源、手动触发、只读连接检查。相比把所有 B/C/D 来源纳入每日自动请求，这种方式不会给官网增加无意义访问，也不会把网络异常误判为岗位变化；相比仅用人工备注，结果能带有实际检查时间和失败类别。

## 工作流

1. 运营人员在任一非自动采集来源旁点击“验证官网连接”。
2. 后端仅对来源的官方职业页发出 `GET` 请求，严格保留 TLS 证书校验、15 秒超时和最多 3 次重定向。
3. HTTP 2xx–3xx 记录为“官网连接正常，仍待专用适配”；非成功状态、TLS 错误或超时记录为“官网连接异常：原因”。
4. 操作回到来源页，页面顶部显示一次性结果提示；该来源行同步展示最近检查与摘要。

## 安全与边界

- 仅允许目录中既有来源；不接受用户输入的任意 URL。
- 不使用 `verify=False`、不绕过 HTTPS 警告、不下载附件、不解析岗位、不创建招聘记录。
- A 类来源已有每日采集机制；连接检查仅提供给 B/C/D 类和已暂停来源作人工诊断。
- 连接失败不自动暂停来源，也不代表岗位结束。

## 验收标准

- B 类来源可从来源页触发检查，并留在来源页看到成功/失败反馈。
- TLS 失败时记录简洁的“HTTPS 证书或连接校验失败”，不泄漏内部异常堆栈。
- HTTP 成功时更新 `last_checked_at` 和 `last_monitor_summary`，但不修改 `is_enabled`、`library_tier` 或岗位表。
- 测试覆盖成功、TLS 失败、非法来源 ID 和页面按钮显示。
