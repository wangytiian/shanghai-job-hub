# B 级岗位人工筛选池设计

日期：2026-10-10。用户明确要求 B 级有真实岗位入库并由人工筛选，授权按项目实际情况决定边界。此设计只改变**岗位入库等级**，不改变来源库 A/B/C/D、日常采集调度或发布权限。

## 问题与目标

当前真实岗位 A=38、B=0、C=75、D=64。岗位初筛只在原文出现“社会招聘/社会人员”时通常给 B；获准的商学院和二工大来源把“除学生受众外其他证据齐全”的候选强制存成 C。C 因而混合了值得人工筛选的完整岗位与真正缺关键证据的弱线索。

目标是让 B 表示“**岗位事实与投递证据已具备、学生资格尚待人工判断**”的实际工作队列，而非发布许可。不能靠改造来源等级、虚构岗位、随机抽样升档或把全部 C 搬进 B 来实现数量。

## 分级与准入

| 岗位等级 | 含义与自动边界 | 后续处理 |
| --- | --- | --- |
| A | 原文有明确实习、应届、校招等学生招聘信号，且未触发硬排除 | 优先人工核验 |
| B | 官方来源可追溯、岗位级正文/单位/上海地点/投递路径可核验、未过期且无校内专属或明确资深经验硬门槛；只缺“立信学生或应届生是否可投”的确认 | 进入人工筛选，保留“受众待确认”标记，禁止直接发布 |
| C | 岗位事实、投递、地点、时效等关键证据不足，或 AI 失败、适配依据无法核验 | 补证据后再判断，不直接发布 |
| D | 进度通知、已截止、明确资深门槛、收费风险、校内专属等明确不适合情形 | 过滤留档 |

专业方向以已有立信覆盖基线（财会金融、商贸物流、管理营销、数据技术、法律行政及通用职能）辅助人工排序，不因“本科”“专业不限”单个词自动宣称适配；教学等偏离目标的岗位由人工筛除。多岗位公告不得让别的岗位的学生/地点/投递证据污染本岗位。

`evaluate_review_intake` 已确认仅缺 `TARGET_AUDIENCE_UNCLEAR` 的 `review_only` 候选，持久化为 B／“普通待核验”，继续保存原 `REVIEW_NOTE` 受众待确认标记。其他 `needs_evidence`、`excluded` 不得走此路径。B 来源的试采、白名单、显式样本导入、限量和来源版本检查保持原样；B 来源不自动产生 B 岗位，也不加入每日 A 来源调度。

普通规则初筛允许岗位级正文中有初级/本科/专科/无硬性经验等弱适配证据且有明确投递路径的岗位进入 B；只有笼统招聘公告、原文不完整、缺投递证据时仍为 C。原有硬过滤始终先执行。无论规则、AI 还是 `review_only` 给出 B，只要学生可投资格并无直接证据，持久化原因都必须保留同一个 `REVIEW_NOTE` 待确认标记；AI 返回 B 不得绕过硬过滤或证据校验。

## 人工确认与发布隔离

新 B 的 `REVIEW_NOTE` 表示**受众尚未确认**。`validate_publishable` 和最终审核必须拒绝仍带该标记的 B，不能因为等级从 C 变 B 就进入公众号或群分发。

复用现有受众证据复核入口：审核员/管理员提交官方证据 URL、连续原文摘录和判断说明；对带标记的 C，确认后升 B；对带标记的 B，确认后仍为 B，但移除待确认标记。两种情况都保持 `status=待核验`，清除旧核验、分数与 AI 建议，递增版本，并写 `ReviewLog` 与 `AuditEvent`。仅真实、未截止、待核验、确认为新招聘的当前事实版本允许确认。若证据只能证明“要求本科/经验优先”而不能证明应届一定可投，人工说明必须保留不确定性，不得对学生宣称招聘方已保证接收。

确认受众之后仍需结构化、六项人工核验、质量阈值、最终审核及分发校验。复采导致事实变化时，撤销旧人工确认并重新分级；原文未变时不得无故冲掉已经完成的人工判断。

## 现有 C 的一次性重判

先只读预览，再备份 SQLite。只处理 `intake_reason` 为既有 `REVIEW_NOTE`、真实、`status=待核验`、`notice_type=新招聘`、未截止且有当前事实指纹的记录；按现有来源准入事实复查硬排除、上海地点、岗位级正文和投递证据。满足者事务内改为 B、保留待确认标记、归零旧核验/建议、递增版本并写审计。已截止、待判断、其他 C 原因、人工已处理记录均不碰；无命中时如实报告而不伪造 B 数量。

不以重写 `REVIEW_NOTE` 文案的方式迁移：历史精确匹配必须兼容。预览和执行按岗位 ID 给出从 C 到 B、跳过原因及变更总数，复跑幂等。系统现有 `_save_detail` 对指纹未变的记录会跳过重筛；一次性重判不得依赖普通定时采集。备份与审计可用于恢复旧等级，不删除任何岗位。

## 验收与非目标

- 单元样本覆盖 A/B/C/D、`review_only→B`、无岗位正文/无投递/已截止/资深经验/校内专属/多岗位污染等反例；B 来源仍不自动调度。
- 端到端测试证明带待确认标记的 B 无法最终通过或分发；人工确认后仍需全套核验。
- 在数据库备份之后执行一次只读预览和有界历史重判，核实 B 数量确实由 0 增至正数、每条有来源与审计记录；报告不能把 B 待筛线索称作可发布岗位。
- 不新增抓取网站、不改变来源 A/B/C/D、不自动发布、不自动给质量分、不承诺日均 1–2 条可发布岗位。
